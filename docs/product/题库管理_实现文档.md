# 题库管理（增删改查）· 实现文档

> 功能定位：为 2026 新托福四种题型（口语「听后复述」「互动面试」、写作「邮件写作」「学术讨论写作」）补齐题库的「查（管理浏览）、改（编辑）、删（删除）」能力。此前题库只有「增」（docx 导入 / 内容采集 / 手动录题三条通道），本文记录 CRUD 收尾的完整实现细节。

---

## 一、功能概述

```
口语空间 / 写作空间 → 「题库管理」卡片 → 管理页（题型 tab + 题目卡片列表）
  → 浏览：列表（标题 + 句数/题数徽章）
  → 编辑：拉详情 → 复用录题表单预填充 → 保存（走去重检测，排除自身旧题干）
  → 删除：confirm 二次确认 → 物理删除（子表+主表）→ 同步清理去重向量缓存
```

核心价值：题库可自主维护——改错别字、修参考答案、删劣质题，不再需要「重跑 docx 全量重建」或进数据库手工改。

---

## 二、产品决策（2026-08-22 确认）

| 决策点 | 结论 |
|---|---|
| 管理入口 | **分散到各模块**：SpeakingHub 与 WritingHub 各加「题库管理」卡片（口语管听后复述+互动面试，写作管邮件+学术讨论） |
| 删除策略 | **物理删除**：SQLite 直接删记录（事务删子表+主表），同步清理 dedup 向量缓存；不加逻辑删除字段 |
| 编辑交互 | **复用录题表单预填充**：ManualAddForm 扩展编辑模式，预填现有内容（含参考答案/核心表达/意群断句），AI 辅助按钮照常可用 |

**明确不做**：不动收藏（数据自足，删题后仍可展示，`topic_title`/`title` 为历史快照不同步）；不动练习记录（`PracticeRecord` 不引用题目 id，零影响）；不做批量删除/搜索/分页；Build a Sentence 不在范围。

## 三、数据流

**删除：**
```
管理页「删除」→ window.confirm → question.delete {category, id}
  → manage.delete_question：
      取旧详情（构造旧题干文本）→ 不存在返回 not_found
      CorpusStore.delete_*（事务：DELETE 子表 + DELETE 主表）
      QuestionEmbeddingStore.delete_by_prompt（清旧题干向量，失败降级）
  → {status:"deleted"} → 前端本地过滤列表
```

**编辑：**
```
管理页「编辑」→ 拉详情（复用现有 GET 接口）→ 预填 ManualAddForm（题型锁定）
提交 → question.update {category, id, ...表单字段, force?}
  → manage.update_question：
      to_items + validate（复用手动录题的校验：复述恰好 7 句、面试恰好 4 题）
      空 chunks 自动断句（复用 chunk_sentences，失败降级整句）
      detect_question_duplicates（exclude_prompt=旧题干，避免与自己旧版本判重）
        重复且非 force → {status:"duplicate", similarity}（前端 confirm 强制）
      CorpusStore.update_*（事务：主表 UPDATE + 子表 DELETE 后全量 INSERT，seq 重排 1..n）
      清旧题干向量 + sync 新题干向量（均失败降级）
  → {status:"updated"} → 回列表重新拉取
```

## 四、数据存储

**零 schema 变更**：复用现有 `corpus.db`（repeat_scenario/repeat_sentence、interview_topic/interview_question、writing_question）与 `dedup.db`（question_embedding），无新增表/字段。

唯一列表增强：`list_scenarios()` 返回值增加 `sentence_count`（LEFT JOIN COUNT），**只增字段**，跟读播放器消费同一接口向后兼容。

## 五、后端模块

| 文件 | 改动 |
|---|---|
| `services/corpus/store.py` | 新增 `delete_repeat_scenario` / `delete_interview_topic` / `delete_writing_question`（物理删除，事务，不存在返回 False）；`update_repeat_scenario` / `update_interview_topic`（主表 UPDATE + 子表全量替换）/ `update_writing_question`（单行 UPDATE）；`list_scenarios` 加 `sentence_count` |
| `services/dedup/question_embedding.py` | 新增 `delete_by_prompt(category, prompt_text)`：按 category + question_key 删向量缓存 |
| `services/dedup/detect.py` | `detect_question_duplicates` 加 `exclude_prompt` 参数：比对时过滤掉与该题干相同的缓存条目（编辑时排除自身） |
| `services/manual/add.py` | `_to_items`/`_validate`/`_VALID_CATEGORIES` 公开化为 `to_items`/`validate`/`VALID_CATEGORIES`（供编辑复用，逻辑不变） |
| `services/corpus/manage.py` | **新增**：`delete_question` / `update_question` 编排（校验 + 去重 + DB 更新 + 向量缓存同步，风格对齐 manual/add.py） |

### 关键实现点

- **旧题干文本构造**：`_get_old_item` 从详情方法取旧数据并转为与 `to_items` 同构的 item，再经 `detect._question_prompt` 构造题干文本（写作取 prompt_en；复述取 7 句拼接；面试取 4 题 prompt_en 拼接）——与去重判据完全一致。
- **向量缓存同步时序（编辑）**：detect（排除旧题干）→ update DB → delete_by_prompt(旧) → sync(新)。先 detect 后删旧，保证重复检测时旧向量仍在缓存中可被 exclude；两步清理/写入均 try/except 降级。
- **子表全量替换**：编辑口语题按「整组替换」处理（7 句/4 题整组提交），seq 重排 1..n；子表自增 id 变化无影响（前端按 seq 消费）。
- **降级惯例**：向量清理/写入失败一律降级不阻断，主流程（DB 删除/更新）不受影响（与项目「降级不阻断」约定一致）。

## 六、后端接口（WebUI mutation，走 WebSocket）

| action | mutation path | 说明 |
|---|---|---|
| `question.update` | `/api/toefl/question/update` | **新增**：编辑一道题（校验 + 去重 + 更新 + 同步向量） |
| `question.delete` | `/api/toefl/question/delete` | **新增**：物理删除 + 清理向量缓存 |

payload / 响应：

- `update`：`{category, id, ...表单字段(与 question.add 相同), force?}` → `{status: "updated" | "duplicate" | "invalid" | "not_found" | "invalid_category", similarity?, message?}`（`invalid` 为表单校验失败，`message` 为中文原因如「缺少主题标题」）
- `delete`：`{category, id}` → `{status: "deleted" | "not_found" | "invalid_category"}`

> 校验失败约定：`question.add` 与 `question.update` 的表单校验失败均返回 `{status: "invalid", "message": 原因}`（HTTP 200 业务状态），**不抛异常**——避免前端透出 `RuntimeError: xxx` 这类技术性报错；前端统一展示 `message`。

**列表/详情查询零新增**：管理页复用现有 GET（`/api/toefl/repeat/scenarios`、`/api/toefl/interview/topics`、`/api/toefl/writing/questions?type=`、三个详情接口）。

## 八、使用方式

1. 进入「托福学习空间 → 口语空间 / 写作空间」，点「题库管理」卡片。
2. 切换题型 tab 浏览题目列表（卡片显示标题 + 句数/题数徽章）。
3. 点「编辑」进入预填表单，修改任意字段（含 AI 自动断句/生成参考），点「保存修改」；若与其他题疑似重复会弹确认，可强制保存。保存成功显示绿色「已保存修改，正在返回列表…」提示，稍后自动回到列表；失败显示红色报错并停留表单。
4. 点「删除」二次确认后物理删除（不可恢复；练习记录与收藏不受影响）。
5. 新增题目仍走「工具 → 内容采集 → 手动录题」（行为不变）。

## 九、已知限制与风险

1. **物理删除不可恢复**：已与产品决策确认；UI 层 confirm 含题目标题 + 「不可恢复」提示。
2. **编辑改 title 后收藏为历史快照**：收藏表冗余存的 `topic_title`/`title` 不同步（收藏的表达本身独立有价值）。
3. **纯 embedding 判据的误判**：编辑后与库内其他题相似度 ≥0.90 会拦截（可 force），与手动录题同一套机制。
4. **向量缓存清理失败会残留**：极端情况下（dedup.db 损坏）残留向量会让相似题被误判重复，可 force 绕过；不影响 DB 主流程。
5. **口语题编辑为整组替换**：子表 id 会变（前端按 seq 消费无影响），不支持只改单句的局部编辑。
