# 知识库分类过滤与判分增强 · 实现文档

> 功能定位：把「内容采集 / 文件上传」从「无标签单一 RAG 库」升级为**纯净的托福个人知识库**——入库前统一大模型判断（只留托福 + 广告必过滤 + 打科目/类型标签），提供分类浏览管理，并接入写作与口语判分的 RAG 增强。
> 本文记录完整实现细节，供后续维护与迭代参考。

---

## 一、功能概述

```
链接 / 文件 → 提取文本 → 大模型判断（考试 + 广告 + 打标）
  → 非托福 / 广告 → 强制忽略（不入库）
  → 托福且非广告 → 打 exam/subject/content_type 标签 → 存 pending
  → 预览（标签 + 过滤原因 + 知识点）→ 确认入库
  → 知识库分类浏览 / 筛选 / 删除
  → 写作 / 口语判分检索增强
```

核心价值：知识库**纯净只服务托福**，判分反馈能引用用户自己收集的备考资料，同时可管理（浏览、筛选、删除）。

---

## 二、产品决策（2026-08-21 确认）

| 决策点 | 结论 |
|---|---|
| 考试范围 | **只留托福**：雅思/GRE 内容入库时过滤 |
| 使用形态 | **判分增强 + 分类浏览管理** |
| 标签来源 | **大模型自动打标 + 人工确认** |
| 广告处理 | **自动识别 + 人工确认，广告必过滤** |
| 文件上传 | **统一都判断**（不再纯 RAG） |
| 判分增强范围 | **写作 + 口语判分**（发音/流利度走音频评测不受影响） |
| 分类浏览管理 | **含删除**（浏览 + 筛选 + 删除，删除走 RAG 全量重建） |

## 三、标签体系

| 维度 | 字段 | 枚举 |
|---|---|---|
| 考试 | `exam` | `toefl` / `ielts` / `gre` / `other` |
| 科目 | `subject` | `speaking` / `writing` / `reading` / `listening` / `vocab` / `grammar` / `general`（综合） |
| 内容类型 | `content_type` | `question`（题目）/ `sample_essay`（范文）/ `methodology`（方法论）/ `experience`（经验贴）/ `vocabulary`（词汇）/ `news`（资讯）/ `ad`（广告） |

**过滤规则**（`_apply_filter`）：`is_ad == true` 或 `exam != "toefl"` → 强制 `category='ignore'`，reason 说明原因（「广告/推广内容，不入库」或「非托福内容（雅思/GRE），不入库」）。

## 四、数据存储

### 4.1 采集记录表扩展（`data/ingest.db`）

在 `ingest_records` 上幂等新增三列（`ALTER TABLE ADD COLUMN`，复用 `_EXTRA_COLUMNS` 迁移）：

```sql
ALTER TABLE ingest_records ADD COLUMN exam         TEXT NOT NULL DEFAULT '';
ALTER TABLE ingest_records ADD COLUMN subject      TEXT NOT NULL DEFAULT '';
ALTER TABLE ingest_records ADD COLUMN content_type TEXT NOT NULL DEFAULT '';
```

标签同时写入 `result_json`（判断结果）与独立列（便于 SQL 筛选）。

### 4.2 RAG 落点（`data/rag/index/`）

RAG 入库时，`Chunk.meta` 记录 `{kind, exam, subject, content_type, url/filename}`，供判分按 `subject` 过滤。

## 五、后端模块

### 5.1 判断层 `analyze_article.py`

- `analyze_article(title, raw_text)`：链接导入用，返回 `{category, reason, exam, is_ad, subject, content_type, items, chunks}`。
- `analyze_tags(title, raw_text)`：**新增**，文件上传用，轻量判断（只输出 `{exam, is_ad, subject, content_type, reason}`，不抽题不分块）。
- 标签做类型校验与默认值兜底：exam 非法 → `other`、subject 非法 → `general`、content_type 非法 → `""`。

### 5.2 存储层 `store.py`

新增方法：
- `list_knowledge_base(subject, content_type, limit)`：列出 `confirmed` 且非 ignore 的记录，解析 `result_json` 计算 `chunks` 数量。
- `list_confirmed_rag()`：返回所有 `confirmed + category='rag'` 的记录（供全量重建）。
- `delete(url)`：物理删除记录。

### 5.3 编排层 `ingest.py`

- `fetch_and_analyze`：判断后经 `_apply_filter` 过滤，标签写入记录。
- `upload_and_prepare`（改为 async）：提取文本 → `analyze_tags` 判断 → 过滤 → 非 ignore 才本地分块 → 存 pending。
- `confirm_ingest`：RAG 分支经 `_build_rag_chunks` 构造带标签 meta 的 Chunk。
- `list_knowledge_base` / `delete_knowledge`：知识库浏览与删除；删除后汇总剩余 RAG 记录全量重建。

### 5.4 RAG 层 `rag/search.py`

- `rag_search(..., subject=None)`：新增 subject 参数，检索时放大候选 `top_k * 5`，按 `meta.subject` 宽松过滤（空 / `general` / 匹配均保留）后取前 `top_k`。
- `rag_rebuild(source, chunks)`：**新增**，全量重建索引（覆盖）；`chunks` 为空时删除索引文件。

### 5.5 判分增强

- 写作 `score_writing.py`：在 `lesson-plan-writing` 检索后追加 `ingested-articles` 检索（`subject="writing"`），合并进教学法反馈；失败降级为空。
- 口语 `llm/scoring.py::score_content`：检索 `ingested-articles`（`subject="speaking"`），把片段注入 system prompt 增强内容评分；失败降级为空。

## 六、后端接口（WebUI mutation，走 WebSocket）

| action | mutation path | 说明 |
|---|---|---|
| `ingest.fetch` | `/api/toefl/ingest/fetch` | 链接导入（判断 + 过滤 + 打标） |
| `ingest.upload` | `/api/toefl/ingest/upload` | 文件上传（判断 + 过滤 + 打标 + 本地分块） |
| `ingest.confirm` | `/api/toefl/ingest/confirm` | 确认入库 |
| `ingest.ignore` | `/api/toefl/ingest/ignore` | 忽略 |
| `ingest.list` | `/api/toefl/ingest/list` | **新增**：列出已入库记录 |
| `ingest.delete` | `/api/toefl/ingest/delete` | **新增**：删除 + 全量重建 RAG |

请求/响应 payload：

- `list`：`{ subject?, content_type? }` → `{ items: [{ id, url, title, source, kind, filename, exam, subject, content_type, chunks, created_at }] }`
- `delete`：`{ url }` → `{ status: "deleted", rebuilt_chunks: N }`

## 八、使用方式

1. 采集：进入「内容采集」，粘贴链接或上传文件，AI 判断后预览展示标签/过滤原因。
2. 确认入库（题目进题库，知识点进 RAG）。
3. 管理：进入「我的知识库」，按科目/类型筛选浏览，删除不需要的记录。
4. 增强：写作/口语判分时自动检索知识库，反馈引用相关知识点。

## 九、已知限制与风险

1. **RAG 删除 = 全量重建**：faiss `IndexFlatIP` 只增难删，删除后重新 embedding 全部剩余 chunk；当前规模（数百条）秒级完成，可接受。
2. **文件判断截断**：`analyze_tags` 喂截断文本（≤8000 字）判断考试/广告/打标，超长文档的打标可能不够精确；分块仍用本地规则（不截断）。
3. **旧数据无标签**：历史 chunk 无 `subject`，判分检索采用宽松匹配（空标签保留），无回归。
4. **大模型误判**：考试/广告判断可能误判，预览人工确认是唯一把关。
5. **判分检索失败降级**：RAG 检索失败一律降级为空，不阻断判分主流程。
