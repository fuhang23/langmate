# 内容去重 · 实现文档

> 功能定位：为「RAG 知识点入库」与「口语/写作题目入库」增加基于 embedding 语义相似度的去重，避免知识库/题库被高度相似或完全相同的重复内容污染。
> 本文记录完整实现细节，供后续维护与迭代参考。

---

## 一、功能概述

```
采集（链接/文件）→ 判断 + 打标 + 分块 → 去重检测（embedding 相似度）
  → 标记 duplicate + similarity → 预览（重复项带「疑似重复 xx%」+「强制入库」勾选）
  → 确认入库（跳过未强制的重复项）→ 返回「入库 N 题 / M 条知识点 / 跳过 K 个重复」
```

覆盖两类去重：
1. **RAG chunk 去重**：两篇高度相似文档的 chunk，若知识库已有相似度 ≥ 阈值的 chunk，则判重复。
2. **题目去重**：2026 新托福四种题型（口语听后复述/互动面试、写作邮件/学术讨论），同一道题（标题可能不同但题干主旨相同）判重复。

---

## 二、产品决策（2026-08-22 确认）

| 决策点 | 结论 |
|---|---|
| 判据技术 | **纯 embedding 余弦相似度**（复用百炼 embedding，零额外 LLM 调用） |
| 去重粒度 | **混合**：听后复述按整组（7 句场景）、互动面试按整组（4 题主题）、写作按单题 |
| 交互 | **提示 + 可强制**：预览列出重复项（附相似度），可勾选「强制入库」 |
| 范围 | 只做四类（不含 Build a Sentence） |

---

## 三、阈值

| 场景 | 默认阈值 | 环境变量 |
|---|---|---|
| RAG chunk | 0.95 | `DEDUP_RAG_THRESHOLD` |
| 题目题干 | 0.90 | `DEDUP_QUESTION_THRESHOLD` |

判据：向量 L2 归一化后，内积 = 余弦相似度（范围 -1~1）。

## 四、数据存储

### 4.1 RAG 去重

复用现有 `data/rag/index/ingested-articles.faiss` 索引：新 chunk 向量在索引里检索 top1，取相似度。无需新增存储。

### 4.2 题目去重

新增独立 SQLite `data/dedup.db`（环境变量 `LANGMATE_DEDUP_DB` 覆盖），表：

```sql
CREATE TABLE question_embedding (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category TEXT NOT NULL,
    question_key TEXT NOT NULL,        -- sha256(prompt_text)[:16]
    prompt_text TEXT NOT NULL,
    embedding_json TEXT NOT NULL,      -- 1024 维向量 JSON
    created_at TEXT NOT NULL,
    UNIQUE(category, question_key)
);
```

- **惰性回填**：首次检测某 category 且缓存为空时，从 `corpus.db` 现有题目（含 docx 导入的题库）一次性回填题干向量。
- **同步**：确认入库成功后，把新题题干向量写入缓存表；删除题目或编辑改题干后，经 `delete_by_prompt` 清理旧向量（见《题库管理_实现文档》）。

## 五、题干文本构造（混合粒度）

| category | 题干构造 |
|---|---|
| writing_discussion / writing_email | 单题 `prompt_en` |
| speaking_repeat | 每个场景 7 句 `text` 拼接 |
| speaking_interview | 每个主题 4 题 `prompt_en` 拼接 |

`question_key = sha256(prompt_text)[:16]`，同一题干文本（逐字相同）命中唯一约束直接幂等。

## 六、后端模块

| 文件 | 职责 |
|---|---|
| `app/services/rag/store.py` | 新增 `RagIndex.search_with_scores(query_vec, top_k)`，返回 `[(Chunk, similarity)]` |
| `app/services/corpus/store.py` | 新增 `iter_questions_for_dedup(category)`，按 category 列出题干文本 |
| `app/services/dedup/question_embedding.py` | `QuestionEmbeddingStore`：题干向量缓存表的增查；`delete_by_prompt(category, prompt_text)` 删除单条缓存（题目删除/编辑改题干后清理，见《题库管理_实现文档》） |
| `app/services/dedup/detect.py` | `detect_rag_duplicates` / `detect_question_duplicates` / `sync_question_embeddings`；`detect_question_duplicates` 支持可选 `exclude_prompt` 参数（编辑题目时排除自身旧题干，避免与自己旧版本判重） |
| `app/services/ingest/ingest.py` | 采集阶段 `_apply_dedup`；`confirm_ingest` 接收强制列表并跳过重复 |

### 6.1 去重检测（detect.py）

- `detect_rag_duplicates(chunks, source, threshold)`：每个 chunk embedding → 索引检索 top1 → 相似度 ≥ threshold 标记 `duplicate`。
- `detect_question_duplicates(items, category, threshold)`：题干 embedding 与同 category 缓存向量暴力余弦比较 → 超阈值标记 `duplicate`。
- 两者失败一律降级为「不重复」，不阻断采集。

### 6.2 确认入库（confirm_ingest）

- 签名：`confirm_ingest(key, force_item_indices=None, force_chunk_indices=None)`。
- 题目类：`_filter_items` 过滤 duplicate 且未强制的 item，入库后 `sync_question_embeddings`。
- RAG 类：按 chunk 索引过滤 duplicate 且未强制的 chunk，`rag_append` 剩余。
- 返回 `{questions, chunks, skipped_questions, skipped_chunks, status}`。

## 九、使用方式

1. 采集（粘贴链接/上传文件）后，预览区自动标出重复项。
2. 重复的题/知识点卡片带「疑似重复（xx% 相似）」标记，可勾选「强制入库」。
3. 点「确认入库」，未勾选的重复项被跳过。
4. 结果区显示「已入库 N 题、M 条知识点（跳过 K 个重复）」。

## 十、已知限制与风险

1. **纯 embedding 判据**：同话题但不同问法的题（如都是「远程办公」但问题不同）可能被误判为重复（阈值 0.90 较高，倾向漏判而非误判）。若需更准可后续加 LLM 精判。
2. **回填时机**：首次去重时惰性回填现有题库，会一次性消耗 embedding（约 150 题，秒级，成本极低）。
3. **同步时序**：题目向量缓存在「确认入库」后才写入；预览阶段的去重只与「已确认入库」的题比较，不与当前批次的 pending 题互相去重。
4. **RAG 去重只对 ingested-articles**：文件上传/链接导入的 RAG 内容统一进该 source，去重也只在该索引内比较。
5. **去重失败降级**：embedding/检索失败一律降级为「不重复」，不阻断主流程（与 RAG 降级模式一致）。
