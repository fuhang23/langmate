# 列表搜索过滤 · 实现文档

> 功能定位：为托福学习空间的九个列表界面统一增加「关键词搜索、实时过滤」能力，让用户在题库/收藏/知识库增长后仍能快速定位目标内容。
> 本文记录完整实现细节，供后续维护与迭代参考。

---

## 一、功能概述

覆盖九个界面（六个组件，其中两个复用两次）：

| 入口 | 组件 | 搜索主字段 |
|---|---|---|
| 口语空间 → 跟读复述（选题） | `RepeatPlayer` | 场景标题 title |
| 口语空间 → 互动面试（选题） | `InterviewPlayer` | 主题标题 title |
| 口语空间 → 题库管理 | `QuestionManageView` | 题目标题 title |
| 口语空间 → 我的收藏 | `FavoritesView` | 英文表达 expression |
| 写作空间 → 写邮件（选题） | `WritingPlayer`（taskType=email） | 题目标题 title |
| 写作空间 → 学术讨论（选题） | `WritingPlayer`（taskType=discussion） | 题目标题 title |
| 写作空间 → 题库管理 | `QuestionManageView` | 题目标题 title |
| 写作空间 → 我的收藏 | `WritingFavoritesView` | 英文表达 expression |
| 托福学习空间 → 我的知识库 | `KnowledgeBaseView` | 摘要标题/标题 |

**技术路线：纯前端本地过滤，零后端改动。** 九个界面的列表数据全部是一次性全量加载（无分页，量级几十~几百条），过滤在组件内完成。

---

## 二、产品决策（2026-08-22 确认）

| 决策点 | 结论 |
|---|---|
| 搜索字段范围 | **仅主字段**：标题/表达本身，不匹配描述、释义、例句等次要字段（也不搜题干正文，后者需后端接口） |
| 关键词行为 | **空格分词 AND 匹配**：多个关键词全部命中（子串、顺序不限）才显示 |
| 技术路线 | 纯前端实时过滤（数据已全量在前端） |

## 三、交互设计

- **输入即过滤**：无需回车或按钮，每次键入立即更新列表
- **大小写不敏感**：英文关键词如 `travel` 可命中 `Travel Plans`
- **中英文子串匹配**：如「面试」命中「模拟面试」
- **多关键词 AND**：`travel plan` 命中需标题同时包含两词（顺序不限）
- **清空按钮**：输入框有值时右侧显示 X，一键清空恢复全量
- **无匹配空态**：统一「未找到与「xxx」相关的内容，换个关键词试试」
- **保留原有空态**：无数据（未收藏/未入库）与搜索无匹配区分展示
- **练习页隐藏**：三个练习播放器的搜索框只在选题阶段显示，进入练习后不渲染
- **题库管理切 tab 清空**：切换题型 tab 时重置搜索词（不同题型标题不通用）
- **知识库叠加筛选**：搜索与现有科目/类型 FilterChip 为 AND 关系（先筛后搜）
- **收藏页分组保留**：过滤组内条目、剔除空分组，分组结构不变；头部副标题在搜索时显示「匹配到 N 个（共 M 个）」

## 四、前端实现

### 4.1 新增 `ListSearchBar.tsx`（统一组件 + 工具函数）

| 导出 | 说明 |
|---|---|
| `matchesKeywords(text, query)` | 纯函数：query 按空白切分、小写化，全部作为子串命中 text（大小写不敏感）返回 true；空查询恒 true |
| `ListSearchBar` | 搜索框组件：Search 图标 + input + 有值时的清空按钮；props `{value, onChange, placeholder}` |
| `NoSearchResult` | 搜索无匹配空态：Search 图标 + 「未找到与「keyword」相关的内容…」 |

### 4.2 各组件接入模式

统一三步：`const [search, setSearch] = useState("")` → header 下插入 `<ListSearchBar/>` → 列表渲染前 `.filter(matchesKeywords)`，无匹配渲染 `<NoSearchResult/>`。

| 组件 | 接入细节 |
|---|---|
| `RepeatPlayer` | 选题分支（select phase）：搜索框 + `scenarios.filter(s => matchesKeywords(s.title, search))`；卡片渲染、练习阶段逻辑不变 |
| `InterviewPlayer` | 同上，过滤 `topics` |
| `WritingPlayer` | 列表分支（`!question`）：过滤 `questions`；原有 error 提示保留 |
| `QuestionManageView` | 题型 tab 下方插入搜索框，过滤 `items`（归一后的 id/title/badge）；`switchCategory` 时 `setSearch("")`；「暂无题目」与「搜索无匹配」两种空态区分 |
| `FavoritesView` | `filteredGroups = groups.map(组内过滤 expression).filter(剔空组)`；副标题搜索时显示匹配数/总数；取消收藏的乐观更新逻辑不受影响（操作原始 groups） |
| `WritingFavoritesView` | 同 FavoritesView |
| `KnowledgeBaseView` | 筛选区顶部插入搜索框；`filtered` 在原 subject/contentType 过滤链上追加 `matchesKeywords(it.summary_title \|\| it.title, search)`；无匹配用 NoSearchResult 替代原「没有符合筛选条件的知识」 |

## 五、使用方式

1. 进入任一列表界面，在标题下方的搜索框输入关键词（支持中文/英文/多词空格分隔）。
2. 列表实时过滤，只显示主字段命中全部关键词的条目。
3. 点输入框右侧 X 或删空输入即恢复全量。
4. 知识库页可组合使用：先点 FilterChip 按科目/类型筛选，再输入关键词细化。

## 六、已知限制与风险

1. **仅主字段**：搜不到描述/释义/例句/题干正文（如需全文检索须新增后端接口，题库列表阶段不返回正文）。
2. **无高亮**：列表项内不高亮命中片段（可后续增强）。
3. **数据量前提**：纯前端过滤适合当前量级（几百条内）；若未来题目/知识库增长到数千条，需评估后端搜索接口。
4. **输入法组合输入**：中文输入法「组词未上屏」阶段不触发过滤（onChange 仅在候选确认后触发），行为符合预期但无专门处理。
