# 口语部分产品形态 —— 聊天模式 & 备考模式

> 阶段：托福模块已上线骨架（侧边栏入口 + 学习仪表盘 + 口语闭环），本期聚焦「口语部分」内部的产品形态设计
> 日期：2026-08-19
> 状态：方案已与用户对齐（4 项关键决策已确认）
> 前置文档：《AI英语学习搭子_产品形态与方向分析.md》

---

## 0. 一句话结论

口语部分拆成**两种模式**，覆盖「能力养成」与「应试提分」两条互补路径：

- **聊天模式（Chat Mode）**：每节课有明确主题/场景，AI 像外教一样有教学法地引导对话、选择性纠错，允许夹杂中文讲解。当前用对讲机回合制跑通，后续升级全双工。
- **备考模式（Exam Mode）**：针对 2026 新托福口语两种题型做专项练习——**Listen and Repeat（跟读复述）** 与 **Take an Interview（互动面试）**，本地资料结构化入库 SQLite，逐题递进 + 评分 + 反馈闭环。

---

## 1. 为什么拆成两种模式

| 维度 | 聊天模式 | 备考模式 |
|---|---|---|
| 目标 | 长期口语能力养成 | 应试提分 |
| 驱动 | 教学法（隐性目标 + 纠错引导） | 题型 + 评分标准 |
| 内容来源 | AI 动态生成场景对话 | 本地结构化题库（docx） |
| 节奏 | 自由、连续对话 | 逐题、计时、判分 |
| 对标 | 豆包通话 + 机构口语课 | cosulabs.ai「一段一段拉上去」 |

两者**不是二选一**，而是同一「口语」入口下的两个 tab。聊天模式练「敢说、会说」，备考模式练「拿分」。数据统一写回同一套 progress 表，仪表盘汇总。

## 2. 聊天模式（Chat Mode）设计

### 2.1 定位

> 日常语音通话，AI 是「懂教学的老师」，不是陪聊。

### 2.2 教学法内核（对标机构口语课）

**每节课有明确主题/场景**（已确认，而非完全自由话题）。AI 设定一个场景（点餐、面试、校园、旅行等），围绕场景对话并纠错。核心循环：

```
场景引入 → AI 提问（开放，逼学生组织语言）
   → 学生作答（英文表达）
   → AI 选择性纠错（只纠 1-2 个核心错误，不打断流利度）
   → AI 复述示范正确表达 → 引导学生再表达一次
   → 自然推进到下一问（始终围绕本课目标）
```

### 2.3 教学法原则（来自机构调研）

1. **有隐性目标**：每节课背后有教学点（如「练过去时叙事」「练虚拟语气」「练让步转折」），AI 的提问与纠错都指向它。
2. **选择性纠错，而非逐句纠**：只纠「影响理解 / 高频复现」的核心错误，避免挫败感；流利度优先。
3. **苏格拉底式引导 > 直接给答案**：学生卡住时递提示、给半句、给关键词，让学生自己构建（Vygotsky 最近发展区）。
4. **允许夹杂中文**：讲解、纠错说明用中文，练习表达用英文——降低认知负担，聚焦口语本身。
5. **复述示范**：AI 纠错后给出正确说法，让学生跟着再说一遍，形成「输入→纠错→再输出」闭环。

### 2.4 技术实现（当前阶段）

- **复用现有对讲机回合制**（TTS 播 → 学生按住说 → ASR → 纠错反馈），**不依赖全双工**。
- **全双工实时语音（可打断）为后续升级**，见记忆/待办清单，与豆包 ASR 一起实现。
- 教学法通过一个 **`chat-mode` Skill** 落地：把「场景设定 + 隐性目标 + 选择性纠错 + 复述示范」写进 system prompt 与引导流程，agent 按此执行。

## 3. 备考模式（Exam Mode）设计

### 3.1 定位

> 针对 2026 新托福口语两种题型，逐题专项练习，对标官方评分标准。

### 3.2 2026 新托福口语题型（已核实）

自 2026-01-21 起，托福口语取消旧「独立 + 综合口语」，改为两种题型，共 11 题、约 8 分钟，**线性固定题序（非自适应）**：

| 题型 | 题量 | 作答时长 | 评分维度 |
|---|---|---|---|
| **Listen and Repeat（跟读复述）** | 7 题 | 8/10/12 秒（逐题递增） | 词语准确性、发音清晰度、语调重音节奏、复述完整性（须逐字复述，不得替换/省略） |
| **Take an Interview（互动面试）** | 4 题 | 每题 45 秒 | 流利度、逻辑连贯、语法、词汇、发音（前 2 题事实经历 → 后 2 题观点论述，递进） |

### 3.3 跟读复述（Listen and Repeat）练习流程

```
播放句子（音频，仅一次）→ 学生跟读复述（计时 8/10/12 秒）
   → ASR 转写 → 逐句比对（发音/重音/意群断句）
   → 评分（对标 4 个官方维度）+ 定位薄弱点（哪个词/哪个音）
   → 重听 + 再复述（迭代）
```

- **判分方案**：复用已跑通的硅基流动 ASR + 现有发音评测工具，逐句比对，先跑通再迭代精细判分（重音/音素级后续增强）。
- 资料句子的 `/` 意群断句标记可用于「重音/停顿」评分参考。

### 3.4 互动面试（Take an Interview）练习流程

```
出题（按主题 + 递进题序）→ 学生 45 秒作答
   → ASR 转写 → 五维评分（流利/逻辑/语法/词汇/发音）
   → 展示参考回答对比 + 核心表达（高亮词组，可收藏）
   → 薄弱点定位 + 下一步建议
```

- **反馈呈现**（已确认）：答完 45 秒后**展示参考回答 + 核心表达，核心表达可收藏积累**（最贴近资料原貌，服务于「词汇/表达积累」）。
- 递进逻辑：第 1-2 题事实/经历 → 第 3 题偏好/对比 → 第 4 题观点/论述。

## 4. 资料入库方案

### 4.1 结论：结构化入库 SQLite，不用 RAG

两份资料（`listen and repeat.docx`、`互动面试.docx`）都是**结构化内容**，不是长文，无需语义检索：

| 资料 | 结构 | 入库方式 |
|---|---|---|
| `listen and repeat.docx` | ~30+ 场景，每场景 = 情景说明 + 7 句（含 `/` 意群标记） | 表 `listen_repeat_scenario` + `listen_repeat_sentence` |
| `互动面试.docx` | 按主题分组，每组 4 题递进，每题 = 题目（英+中）+ 参考回答 + 核心表达 | 表 `interview_topic` + `interview_question` + `interview_expression` |

> 为什么不用 RAG：RAG 解决「从大段资料里语义检索相关片段」，但这里需要的是「精确按题型/主题/题号取题、保留意群断句、逐题递进、核心表达精确对应」。结构化 SQLite 查询更直接、可控、可精确出题。

### 4.2 建议表结构（接口级）

```sql
-- 跟读复述
listen_repeat_scenario(id, title, context_prompt, difficulty)
listen_repeat_sentence(id, scenario_id, seq, text, chunks_json)  -- chunks 存意群断句

-- 互动面试
interview_topic(id, title, cefr_hint)
interview_question(id, topic_id, seq, prompt_en, prompt_zh, reference_answer, core_expressions_json, time_limit)
```

### 4.3 数据来源与版权

- 本地资料有版权归属（果实托福/青山学堂等）。**自用无碍，产品化商用前需解决授权**（与《产品形态与方向分析》第 11 节一致）。
- `新托福《青山口语Interview高频预测题》.pdf` 为预测题，可作为面试题库补充，需先解析（pdf）再入库。

## 5. 参考产品洞察

### 5.1 cosulabs.ai（用户指定参考）

- 核心理念："**不是模糊地练很多题，而是把英语口语一段一段拉上去**"——分段式精准提升，反对题海。
- 有 Dashboard 看学习记录/进度。
- 借鉴点：备考模式要「一段一段拉上去」——跟读逐句攻、面试逐题攻，而非随机刷题；进度写回仪表盘。

### 5.2 豆包语音通话（用户指定参考）

- 借鉴点：聊天模式的目标体验 = 豆包通话那种「自然、连续、可打断」的实时语音，但由**教学目标驱动**，不是漫聊。

## 7. 落地建议（分阶段）

1. **阶段 A（备考模式 · 跟读复述 MVP）**：解析 `listen and repeat.docx` 入库 → 逐句播放/复述/评分闭环 → 复用现有 ASR 判分。
2. **阶段 B（备考模式 · 互动面试 MVP）**：解析 `互动面试.docx` 入库 → 45 秒作答 → 五维评分 → 参考回答 + 核心表达（可收藏）。
3. **阶段 C（聊天模式 MVP）**：`chat-mode` Skill + 场景主题库 + 对讲机回合制教学法闭环。
4. **阶段 D（升级）**：全双工实时语音 + 豆包 ASR + 跟读精细判分（重音/音素级）。

进度数据全程写回 progress 表，仪表盘统一展示（口语部分下再细分题型维度）。
