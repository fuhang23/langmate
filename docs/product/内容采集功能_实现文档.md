# 内容采集功能 · 实现文档

> 功能定位：把微信公众号文章「半自动」转化为可练习的题库 / 可检索的知识库。
> 本文记录功能的完整实现细节，供后续维护与迭代参考。

---

## 一、功能概述

「内容采集」让用户手动粘贴一篇公众号文章链接，系统自动完成：

```
抓取正文 → 大模型判断归属 → 结构化提取 → 预览 → 用户确认 → 入库
```

核心价值：**让题库/知识库「自动生长」**，用户看到好的备考文章，一键转成可练习的题目或可检索的知识点，无需手工整理。

**设计原则**：半自动（人工提供 URL + 预览确认把关），不自动抓取公众号（微信无公开订阅接口，自动抓取脆弱易失效）。

---

## 二、交互流程

```
用户在「托福学习空间 → 工具 → 内容采集」粘贴 URL
  → 点「导入」
  → 前端显示「正在抓取文章并由大模型判断归属…」
  → 出预览：分类 + 判断理由 + 题目列表 / 知识点列表
  → 用户「确认入库」或「忽略」
     确认 → 题目写入 corpus.db / 知识点追加 RAG → 状态 confirmed
     忽略 → 状态 ignored，不入库
```

**关键点**：预览确认是人工把关环节，避免大模型误判污染题库/知识库。

---

## 三、数据流

```
URL
  ├─ ① 抓正文（httpx 直连 mp.weixin.qq.com，正则提取 js_content）
  ├─ ② 存 ingest_records（status=pending，raw_text 全文）
  ├─ ③ 大模型 chat_json 判断 → result_json（category/items/chunks）
  ├─ ④ 前端预览 result_json
  └─ ⑤ 确认
       ├─ 题目 → corpus.db（writing_question / repeat_* / interview_* 表）
       └─ 知识点 → faiss 增量追加 + .json 元数据
```

---

## 四、数据存储

### 4.1 采集记录表 `ingest_records`（`data/ingest.db`）

```sql
CREATE TABLE ingest_records (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    url         TEXT NOT NULL UNIQUE,   -- 原文链接（去重键）
    title       TEXT NOT NULL DEFAULT '',
    source      TEXT NOT NULL DEFAULT '',  -- 公众号名称（如「果实托福」）
    raw_text    TEXT NOT NULL DEFAULT '',  -- 抓取的原始正文全文
    category    TEXT NOT NULL DEFAULT '',  -- 大模型判断归属
    result_json TEXT NOT NULL DEFAULT '',  -- 预览数据（题目/知识点 JSON）
    status      TEXT NOT NULL DEFAULT 'pending',  -- pending / confirmed / ignored
    created_at  TEXT NOT NULL
);
```

**为什么存 `raw_text` 全文**：
1. 去重（`url` UNIQUE）；
2. 重解析（解析错了可从原文重跑，不必重新抓取）；
3. 版权溯源（保留 `source` + `url`，商用前可标注来源）。

### 4.2 题库落点（`data/corpus.db`）

| category | 目标表 |
|---|---|
| writing_discussion / writing_email | `writing_question` |
| speaking_repeat | `repeat_scenario` + `repeat_sentence` |
| speaking_interview | `interview_topic` + `interview_question` |

### 4.3 RAG 落点（`data/rag/index/`）

采集文章统一进入独立 source **`ingested-articles`**（与固定文档 `lesson-plan-writing` 分开），文件：
- `ingested-articles.faiss`（向量索引）
- `ingested-articles.json`（chunk 原文 + metadata）

## 六、后端接口（WebUI mutation，走 WebSocket）

| action | mutation path | 说明 |
|---|---|---|
| `ingest.fetch` | `/api/toefl/ingest/fetch` | 抓取 + 判断 + 存 pending，返回预览（async，超时 120s） |
| `ingest.confirm` | `/api/toefl/ingest/confirm` | 确认入库 |
| `ingest.ignore` | `/api/toefl/ingest/ignore` | 忽略 |

请求/响应 payload：

- `fetch`：`{ url }` → `{ url, title, source, category, reason, items, chunks, status }`
- `confirm`：`{ url }` → `{ status: "confirmed", questions: N, chunks: M }`
- `ignore`：`{ url }` → `{ status: "ignored" }`

均走 `_mutation_payload` 读 body，`check_api_token` 校验，`services.ingest` 惰性导入（nanobot 脱离 langmate 仍可运行）。

## 七、大模型判断契约（`analyze_article`）

### 7.1 category 枚举

| category | 含义 |
|---|---|
| `writing_discussion` | 学术讨论写作题（教授提问 + 同学回帖 + 范文） |
| `writing_email` | 邮件写作题（场景 + 任务清单 + 范文） |
| `speaking_repeat` | 跟读复述题（可标注意群） |
| `speaking_interview` | 面试口语题（45 秒即兴 + 参考回答） |
| `rag` | 备考方法论 / 知识点（非题目） |
| `ignore` | 与托福备考无关（广告/推广） |

### 7.2 输出结构

```json
{
  "category": "writing_discussion",
  "reason": "一句话判断理由",
  "items": [ /* 题目，结构随 category */ ],
  "chunks": [ /* rag 时：{text, title} */ ]
}
```

**items 按题型**：
- 写作：`{ task_type, title, prompt_en, reference_answer }`
- 跟读：`{ title, sentences: [{ seq, text, chunks }] }`（chunks 是意群断句）
- 面试：`{ title, questions: [{ seq, prompt_en, prompt_zh, reference_answer, core_expressions }] }`

**提取原则**：英文题目保留原文不改写；提取不到填空数组，不编造。

## 八、入库方法（`corpus/store.py`，均幂等）

| 方法 | 去重键 | 说明 |
|---|---|---|
| `add_writing_questions(items)` | `task_type + title` | 写入 `writing_question` |
| `add_speaking_repeat(items)` | `repeat_scenario.title` | 写入场景 + 句子（chunks 存 JSON） |
| `add_speaking_interview(items)` | `interview_topic.title` | 写入主题 + 题（core_expressions 存 JSON） |

跟读题把一篇文章的句子归为一个新 `repeat_scenario`（title=文章标题），句子按 seq 排列，`suggested_seconds` 由现有 seq 映射自动算；面试题同理，题数不强制 4。

## 九、RAG 增量追加

- `RagIndex.append(vectors, chunks)`：faiss `index.add` 增量追加（不重建已有向量）。
- `rag_append(source, chunks, index_dir)`：首次创建索引、后续增量追加，失败向上抛异常（确认入库时应感知失败）。
- 采集文章 source = `ingested-articles`，与固定文档 `lesson-plan-writing` 分开，互不影响。
- **删除策略**：faiss `IndexFlatIP` 只增难删，删除/更正走「逻辑删除 + 全量重建」；当前 chunk 规模小，全量重建几秒完成。

## 十一、使用方式

1. 进入「托福学习空间 → 工具 → 内容采集」。
2. 粘贴公众号文章链接（如 `https://mp.weixin.qq.com/s/...`）。
3. 点「导入」，等待大模型判断（约 1~3 秒）。
4. 检查预览结果，点「确认入库」或「忽略」。
5. 题目类：去对应模块（写作/口语）验证新题已出现；RAG 类：后续判分/答疑会自动检索到。

---

## 十二、已知限制与风险

1. **抓取稳定性**：微信无公开 API，`httpx` 直连依赖文章详情页匿名可访问；偶尔触发「环境异常验证页」会抓取失败（报「未能提取正文」）。届时可考虑改用 Jina Reader 或手动粘贴文本。
2. **版权**：抓取的是第三方公众号原创内容，个人学习自用无碍，**商用前必须解决授权**（`ingest_records` 已保留 `source`/`url` 供溯源）。
3. **大模型误判**：预览确认环节是唯一把关，误判仍可能漏网；后续可加「置信度阈值 + 人工 review 队列」。
4. **RAG 删除**：当前只能「逻辑删除 + 全量重建」，尚未实现按条目精确删除。
5. **口语题质量**：跟读/面试题由大模型从文章生成，质量不如人工整理的结构化 docx 资料，需预览时人工把关。

---

## 十三、依赖

- 后端：`httpx`（抓取）、`chat_json`（DeepSeek 判断）、`faiss-cpu` + `numpy`（RAG）、`pypdf`（RAG 固定文档）。
- 环境变量：`DEEPSEEK_API_KEY`（判断）、`BAILIAN_API_KEY`（RAG embedding，可选，未配置则 RAG 入库失败但题目入库正常）。
- 数据库：`data/ingest.db`（采集记录）、`data/corpus.db`（题库）、`data/rag/index/`（向量索引）。
